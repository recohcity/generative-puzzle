# Generative Puzzle 扩展拼图切割模式设计方案

**版本**：v1.0
**日期**：2026-08-01
**状态**：玩法设计提案
**适用范围**：自由模式、禅意模式、每日挑战、盲拼模式及未来社区挑战

## 1. 设计结论

当前项目已经具备四种切割模式：直线、斜线、曲线、碎裂。下一阶段不应继续堆叠更多“线条角度”，而应建立一套可组合的切割语法：

```text
几何生成器（Pattern）
    × 规则变异器（Modifier）
    × 游戏场景（Scenario）
    × 视觉主题（Theme）
```

这样可以让同一种几何切割产生多种游戏体验，也能避免切割按钮不断增加、玩家却无法理解差异的问题。

最值得优先开发的三个方向是：

1. **花窗铅线**：将现有碎裂模式升级为项目的视觉招牌。
2. **雷击裂纹**：提供与 Voronoi 完全不同的自然拓扑和推理方式。
3. **玩家亲自下刀**：让玩家从单纯解谜者变成拼图的共同创作者。

## 2. 当前实现基线

当前四种模式并不是四套完全独立的几何体系：

| 当前模式 | 现有实现 | 玩家感受 | 扩展方向 |
|---|---|---|---|
| 直线 | 线段生成器 + 多边形分割 | 规则、易读、适合入门 | 网格、蒙德里安、波纹 |
| 斜线 | 线段生成器 + 随机角度 | 方向变化、三角形增多 | 晶格、交叉、流场 |
| 曲线 | 径向 Bezier 网络 | 扇形、花朵、放射状 | 螺旋、环形、叶脉、流体 |
| 碎裂 | Voronoi 胞腔剖分 | 随机、非规则、马赛克 | 花窗、蜂巢、三角晶格、加权细胞 |

相关实现：

- [PuzzleGenerator](../utils/puzzle/PuzzleGenerator.ts)：根据切割类型选择生成分支。
- [NetworkCutter](../utils/puzzle/graph/NetworkCutter.ts)：当前曲线模式的径向曲线网络。
- [MosaicGenerator](../utils/puzzle/MosaicGenerator.ts)：当前碎裂模式的 Voronoi 剖分。
- [puzzleUtils](../utils/puzzle/puzzleUtils.ts)：当前直线与斜线模式的多边形线段切割。
- [ScoreCalculator](../packages/game-core/src/utils/score/ScoreCalculator.ts)：当前切割类型难度系数与分数逻辑。

当前四种模式的体验差异主要来自碎片几何。后续模式必须进一步改变玩家的判断方式，而不能只改变颜色、角度或随机程度。

## 3. 设计原则

### 3.1 每种模式必须改变解题线索

玩家应该因为不同模式而采用不同策略：

| 解题线索 | 适合的模式 |
|---|---|
| 方向和角度 | 直线、斜线、晶格 |
| 中心与层级 | 环形、曼陀罗、等高线 |
| 邻接关系 | 花窗、蜂巢、Voronoi |
| 分叉和拓扑 | 裂纹、叶脉、迷宫 |
| 递归结构 | 分形、递归裂变 |
| 互补接口 | 榫卯、经典拼图 |
| 记忆和信息缺失 | 盲拼、无边框、幽灵碎片 |
| 路径规划 | 一笔切、迷宫、玩家亲自下刀 |

### 3.2 几何模式、规则模式和场景模式分离

不建议把以下内容全部设计成 `CutType`：

- 花窗、裂纹、螺旋属于几何生成器。
- 盲拼、无边框、诱饵碎片、重力属于规则变异器。
- 禅意、每日、竞速、双人属于游戏场景。

推荐的数据结构方向：

```text
PuzzleConfig
├── pattern: CutPattern
├── modifier: PuzzleModifier[]
├── scenario: GameScenario
├── theme: VisualTheme
└── seed: string
```

### 3.3 视觉惊艳必须服务于可解性

所有模式必须满足：

- 生成结果可完成。
- 不产生无法拖拽的极小碎片。
- 不产生大量完全相同的碎片形状。
- 相邻碎片能够提供足够的判断线索。
- 难度增加来自推理复杂度，而不是纯粹的信息缺失。

## 4. 几何切割模式库

以下模式按几何语法分组。优先级分为：

- **P0**：建议首批开发，具有项目代表性。
- **P1**：核心扩展，适合形成长期内容。
- **P2**：实验室模式，适合高阶玩家或活动。

实现成本仅表示相对复杂度：低、中、高。

### 4.1 线性与结构化切割

#### 4.1.1 蒙德里安递归分割

**建议标识**：`mondrian-bsp`

使用递归矩形分割，不是普通横竖网格：

- 先生成少量大区域。
- 只对部分区域继续分割。
- 形成大小不均匀的矩形、条形和方块。
- 可以使用红、黄、蓝、黑、白等主题色。

玩家需要判断区域层级和尺寸，不再只是寻找横竖对齐线。

**难度参数**：递归深度、长宽比、空白区域比例、区域最小面积。

**优先级**：P1。**成本**：低。

#### 4.1.2 波纹切割

**建议标识**：`wave-ripple`

使用正弦波、阻尼波或两组干涉波切割：

- 平行水波。
- 中心冲击波。
- 多频率干涉。
- 波纹与直线混合。

适合水面、声波、沙丘、风场等视觉主题。

**难度参数**：波长、振幅、频率、干涉数量、相位偏移。

**优先级**：P1。**成本**：中。

#### 4.1.3 蜂巢与晶格

**建议标识**：`honeycomb-lattice`、`triangular-lattice`、`diamond-lattice`

使用六边形、三角形、菱形或混合晶格：

- 规则晶格适合入门和竞速。
- 局部扭曲可以增加难度。
- 缺失一个关键单元可以形成特殊挑战。
- 三角晶格可以生成低多边形艺术风格。

**难度参数**：晶格方向、扭曲强度、缺失单元数量、局部变形区域。

**优先级**：P1。**成本**：中。

### 4.2 放射、环形与曲线切割

#### 4.2.1 螺旋星轨

**建议标识**：`spiral-orbit`

使用阿基米德螺旋、对数螺旋和环形轨道：

- 生成弯月形、扇形和轨道状碎片。
- 碎片旋转方向具有连续性。
- 适合银河、飓风、贝壳、唱片等主题。

当前曲线模式是径向放射，螺旋模式可以提供完全不同的曲线体验。

**难度参数**：螺旋圈数、中心偏移、弯曲程度、轨道交叉数量。

**优先级**：P0。**成本**：中。

#### 4.2.2 环形曼陀罗

**建议标识**：`mandala-rings`

使用同心圆、放射线和局部弧线的复合结构：

- 中心区域作为核心碎片。
- 外圈按环带分层。
- 支持 4、6、8、12 重对称。
- 适合禅意模式、短局挑战和节庆主题。

**难度参数**：环数、放射线数量、对称阶数、环宽变化。

**优先级**：P1。**成本**：中。

#### 4.2.3 等高线地形

**建议标识**：`topographic-contour`

生成类似地图等高线的多层闭合曲线：

- 内圈、过渡圈和外圈形成自然层级。
- 局部可以加入河流、岛屿和山脊。
- 颜色可以按“高度”渐变。
- 玩家通过层级关系寻找位置。

非常适合与盲拼、无边框和低对比度主题组合。

**难度参数**：层数、闭合率、轮廓偏移、局部断裂、噪声强度。

**优先级**：P0。**成本**：中。

### 4.3 自然与有机切割

#### 4.3.1 花窗铅线

**建议标识**：`stained-glass-lead`

这是现有碎裂模式的艺术化升级：

- 使用加权 Voronoi 或受控细胞剖分。
- 种子点根据视觉重心进行加权。
- 相邻碎片之间显示宽度不同的铅条。
- 边缘加入轻微波动、缺口和玻璃质感。
- 完成后还原为完整彩色玻璃作品。

它应该成为项目最具识别度的切割模式，而不是单纯的随机多边形模式。

**难度参数**：细胞数量、细胞面积方差、边缘复杂度、铅条宽度、主体区域密度。

**优先级**：P0。**成本**：中到高。

#### 4.3.2 雷击裂纹

**建议标识**：`impact-crack`

从一个或多个撞击点向外生成自然裂纹：

- 主裂纹不断分叉。
- 裂纹方向受随机向量场影响。
- 中心碎片较大，外圈碎片更加细长。
- 可以模拟玻璃、冰、岩石和陶瓷。

玩家需要沿着裂纹和邻接关系推理，与 Voronoi 的均匀胞腔形成明显差异。

**难度参数**：撞击点数量、分叉率、裂纹弯曲度、外圈细碎度、裂纹深度。

**优先级**：P0。**成本**：中到高。

#### 4.3.3 叶脉与河网

**建议标识**：`branching-vein`

将当前径向网络扩展为树状分叉网络：

- 主干、支流和末梢拥有不同宽度。
- 分叉角度逐层变化。
- 可生成叶脉、河流、闪电、神经元和珊瑚。
- 不要求所有切割都从同一个中心发出。

**难度参数**：分叉层数、分叉概率、主干数量、网络弯曲度、末梢密度。

**优先级**：P1。**成本**：高。

#### 4.3.4 流体场

**建议标识**：`flow-field`

根据向量场生成切割路径：

- 风场。
- 漩涡。
- 河流。
- 烟雾。
- 磁场。
- 星云轨迹。

碎片会拥有一致的流动方向，适合动态背景和主题化关卡。

**难度参数**：涡旋数量、场强、流线密度、方向变化、路径交叉率。

**优先级**：P1。**成本**：高。

### 4.4 细胞、递归与数学切割

#### 4.4.1 递归裂变

**建议标识**：`recursive-fracture`

通过递归算法逐层切割：

- 四叉树裂变。
- Sierpiński 三角形。
- Koch 雪花。
- 分形花朵。
- 树枝式递归。

每块碎片可以记录裂变层级，形成收集和进度系统。

**难度参数**：递归深度、每层切割概率、最小面积、局部缺失率。

**优先级**：P1。**成本**：中。

#### 4.4.2 准晶体

**建议标识**：`quasicrystal`

使用非周期性图案：

- 局部看似重复，整体永远不完全重复。
- 相邻区域拥有近似但不相同的几何关系。
- 适合高阶玩家和实验室模式。

**难度参数**：对称阶数、扰动强度、局部重复率、碎片密度。

**优先级**：P2。**成本**：高。

#### 4.4.3 万花筒对称

**建议标识**：`kaleidoscope-symmetry`

使用镜像、旋转和对称轴生成高度对称的切割：

- 2、4、6、8 重对称。
- 对称轴本身也是切割线。
- 同形碎片可以制造方向混淆。
- 完成后整张图像像万花筒一样展开。

**难度参数**：对称阶数、重复单元数量、镜像扰动、旋转自由度。

**优先级**：P1。**成本**：中。

### 4.5 结构和接口切割

#### 4.5.1 榫卯接口

**建议标识**：`jigsaw-interlock`

为相邻边生成互补接口：

- 半圆凸起和凹槽。
- 三角榫卯。
- 燕尾榫。
- 机械卡扣。
- 藤蔓或水晶互锁。

它不一定最具原创性，但触感、吸附感和完成反馈都很强，适合大众玩家。

**难度参数**：接口数量、接口相似度、接口深度、旋转自由度、边缘噪声。

**优先级**：P1。**成本**：高。

#### 4.5.2 迷宫切割

**建议标识**：`maze-cut`

让切割线本身形成迷宫或通路网络：

- 碎片之间形成明确拓扑路径。
- 设置入口、出口、死路和环路。
- 完成后路径逐步亮起。
- 可以要求玩家恢复完整道路，而不仅是轮廓。

**难度参数**：路径长度、分叉数、死路数量、环路数量、入口出口距离。

**优先级**：P1。**成本**：高。

#### 4.5.3 机械齿轮

**建议标识**：`clockwork-gear`

使用圆弧、同心结构和齿轮接口：

- 不同半径的机械环。
- 齿轮齿形拼接。
- 多个旋转中心。
- 完成后齿轮联动转动。

适合蒸汽朋克、钟表和机械城市主题。

**难度参数**：齿轮数量、旋转中心数量、齿形相似度、环形层数。

**优先级**：P2。**成本**：高。

## 5. 规则变异器

规则变异器不改变基础切割几何，而改变玩家获取信息、移动碎片或完成拼图的方式。

### 5.1 玩家亲自下刀

**建议标识**：`player-cut`

玩家用鼠标或手指在形状上划线，生成自己的切割方案：

- 切割线必须穿过形状边界。
- 可以限制切割次数。
- 线条越连贯、越接近目标风格，评价越高。
- 生成后立即进入拼图阶段。

这是从“自动生成拼图”走向“玩家创作拼图”的关键玩法。

### 5.2 一笔切

**建议标识**：`one-stroke`

所有切割线必须组成一条连续路径：

- 不能抬笔。
- 不能重复经过同一区域。
- 可以使用 Euler 路径或 Hamilton 路径规则。
- 完成后展示玩家切割轨迹。

### 5.3 逐层再切

**建议标识**：`progressive-recut`

第一层完成后，部分区域再次裂开：

```text
简单轮廓 → 局部裂变 → 隐藏碎片 → 最终复原
```

适合长局、章节制和高难度挑战。

### 5.4 盲切

**建议标识**：`memory-cut`

- 开始前短暂展示完整切割结构。
- 拼图过程中隐藏目标轮廓或切割线。
- 通过记忆、颜色、边缘和邻接关系完成。
- 按提示次数获得 S/A/B/C 评级。

该变异器与 [盲拼模式设计](modes/blind-mode-design-v1.0.md)直接兼容。

### 5.5 无边框

**建议标识**：`borderless`

- 取消碎片描边。
- 只保留颜色、纹理和阴影。
- 高难度下使用相近颜色。
- 拼对后边界短暂发光确认。

### 5.6 诱饵碎片

**建议标识**：`decoy-pieces`

生成少量不属于答案的碎片：

- 诱饵来自相邻区域、镜像区域或同主题碎片。
- 玩家需要判断哪些碎片属于当前拼图。
- 诱饵数量必须受到上限控制，避免变成纯随机排除题。

### 5.7 结构锁

**建议标识**：`locked-order`

碎片按照特定顺序才能完成：

- 先中心、后外圈。
- 先主干、后分支。
- 先四个关键节点、后普通区域。
- 错误区域不会失败，但不会产生吸附。

### 5.8 重力与漂浮

**建议标识**：`gravity`、`floating`、`orbiting`

碎片不再静止：

- 重力向下坠落。
- 水中缓慢漂浮。
- 沿轨道旋转。
- 被中心旋涡吸引。
- 受风场轻微推移。

这类规则应作为高级变体，不建议默认开启。

### 5.9 幽灵碎片

**建议标识**：`ghost-pieces`

碎片只显示轮廓、阴影或局部颜色：

- 靠近目标区域后逐渐显形。
- 拼对后颜色恢复。
- 适合夜间、禅意和盲拼主题。

### 5.10 二选一切割

**建议标识**：`branching-choice`

每完成一阶段，系统提供两个下一阶段切割方案：

- 碎片少但边缘复杂。
- 碎片多但结构规则。
- 高倍率但没有提示。
- 低倍率但拥有更宽松的磁吸。

它可以为拼图加入轻度 Roguelite 路线选择感。

## 6. 场景与切割模式组合

几何模式和游戏场景应组合，而不是互相重复。

| 组合 | 核心体验 |
|---|---|
| 花窗铅线 + 禅意 | 安静、艺术、适合长时间沉浸 |
| 雷击裂纹 + 每日挑战 | 每天面对同一张“灾变现场” |
| 螺旋星轨 + 盲拼 | 依靠方向和旋转记忆 |
| 等高线 + 无边框 | 通过层级和面积推理 |
| 迷宫 + 一笔切 | 生成和解题都具有路径感 |
| 递归裂变 + 逐层再切 | 越拼越复杂，适合长局 |
| 榫卯接口 + 双人竞速 | 拼接手感强，容易产生对抗 |
| 流体场 + 漂浮 | 更像可玩的动态艺术装置 |
| 蜂巢 + 诱饵碎片 | 规则清晰但高压 |
| 万花筒 + 结构锁 | 视觉惊艳并要求固定顺序 |

## 7. 推荐的模式分层

未来 UI 不应把所有模式直接排列成大量按钮，建议使用六个切割家族：

```text
切割家族
├── 线性：直线、斜线、蒙德里安、波纹
├── 放射：曲线、环形、螺旋、曼陀罗
├── 细胞：碎裂、花窗、蜂巢、三角晶格
├── 自然：裂纹、叶脉、流体、等高线
├── 结构：榫卯、迷宫、递归、机械
└── 实验室：准晶体、分形、玩家下刀

变异条件
├── 盲拼
├── 无边框
├── 诱饵碎片
├── 重力
├── 逐层再切
├── 一笔切
└── 限时

游戏场景
├── 自由
├── 禅意
├── 每日
├── 竞速
└── 双人或社区
```

每个切割家族应提供预览缩略图和一句“解题提示”，而不是只展示名称。

## 8. 开发优先级

### 阶段一：建立新的视觉招牌

目标：让玩家一眼看到项目区别于普通拼图游戏的地方。

1. `stained-glass-lead` 花窗铅线
2. `impact-crack` 雷击裂纹
3. `spiral-orbit` 螺旋星轨
4. `topographic-contour` 等高线

### 阶段二：扩大解题类型

目标：让玩家不只是在寻找相同轮廓。

1. `recursive-fracture` 递归裂变
2. `honeycomb-lattice` 蜂巢晶格
3. `jigsaw-interlock` 榫卯接口
4. `maze-cut` 迷宫切割
5. `kaleidoscope-symmetry` 万花筒对称

### 阶段三：建立长期玩法

目标：让玩家反复回来，而不是只试玩一次。

1. `player-cut` 玩家亲自下刀
2. `one-stroke` 一笔切
3. `progressive-recut` 逐层再切
4. `branching-choice` 二选一切割
5. `memory-cut` 盲切
6. 同种子每日挑战和好友挑战

### 阶段四：实验室与社区内容

目标：为高阶玩家和创作者提供持续的新鲜感。

1. `quasicrystal` 准晶体
2. `clockwork-gear` 机械齿轮
3. `flow-field` 流体场
4. 自定义切割编辑器
5. 用户分享种子、规则和主题

## 9. 技术架构建议

### 9.1 生成器接口

每种几何模式应实现统一的生成接口：

```text
CutPatternGenerator.generate({
  shape,
  difficulty,
  seed,
  options
}) -> PuzzleGeometry
```

`PuzzleGeometry` 不应只返回普通点数组，还应能够携带切割拓扑和边界信息。

### 9.2 边界元数据

普通直线模式使用 `Point[]` 足够，但以下模式需要保留额外数据：

- 榫卯：互补边和接口类型。
- 曲线、波纹、螺旋：Bezier 或弧线控制点。
- 花窗：共享铅线 ID 和宽度。
- 迷宫：碎片邻接图。
- 动态模式：速度、轨道和运动约束。

建议的边界概念：

```text
PieceBoundary
├── edgeType: line | curve | arc | tab | crack
├── neighborPieceId
├── sharedEdgeId
├── direction
├── controlPoints
└── lockProfile
```

### 9.3 随机种子

每日挑战、排行榜和好友 PK 必须使用确定性种子：

- 相同种子生成相同形状。
- 相同种子生成相同切割。
- 相同种子生成相同碎片初始状态。
- 服务器可以重新验证结果。
- 玩家可以分享短种子或挑战码。

新生成器不应直接依赖不可控的全局 `Math.random()`，应支持注入 `RandomSource`。

### 9.4 几何质量验证

生成后至少检查：

1. 碎片面积不低于设备相关最小面积。
2. 所有碎片都位于原始形状内部。
3. 碎片之间不发生意外重叠。
4. 碎片总面积接近原始形状面积。
5. 不产生自交多边形。
6. 碎片数量落在难度目标范围内。
7. 旋转后仍能稳定吸附。
8. 移动端触控目标不小于可操作阈值。

### 9.5 性能要求

- 几何生成应与 Canvas 渲染解耦。
- 高复杂度剖分优先放入 `game-core` 或 Web Worker。
- 生成阶段允许稍慢，但局内拖拽必须保持 60FPS。
- 曲线采样、图网络求面和高密度 Voronoi 不应在每帧重复计算。
- 生成后的碎片边界应支持缓存和 OffscreenCanvas AOT Cache。

### 9.6 难度和计分

不要只用“新模式倍率更高”表达难度。建议由以下维度共同计算：

```text
effectiveDifficulty =
  pieceCount
  + minimumPieceArea
  + edgeSimilarity
  + rotationUncertainty
  + adjacencyComplexity
  + informationLoss
  + motionPressure
```

评分校准应结合真实数据：平均完成时间、提示率、重开率、移动端失败率和玩家放弃率。

## 10. 反模式和非目标

以下扩展不应单独占用一个重要模式入口：

- 仅增加更多固定角度。
- 仅改变碎片颜色或纹理。
- 仅把 Voronoi 的随机程度调高。
- 仅增加碎片数量而不增加新的推理线索。
- 用更高倍率掩盖可玩性不足。
- 通过过小碎片制造虚假的高难度。
- 在移动端使用无法准确拖拽的细长碎片。

## 11. 成功标准

### 11.1 玩法层

- 玩家能用一句话说出新模式和已有模式的区别。
- 不看教程也能在第一局理解主要线索。
- 新模式的失败主要来自判断错误，而不是生成异常。
- 同一模式在不同种子下仍然有稳定的核心体验。

### 11.2 内容层

- 每个几何家族至少有一种代表模式。
- 同一个几何模式可以与每日、禅意和盲拼组合。
- 每个模式拥有独立的视觉预览、名称和中英文文案。
- 高阶模式可以形成徽章、称号或收藏记录。

### 11.3 工程层

- Chrome、Safari、微信内置浏览器均可正常完成。
- 竖屏、横屏、iPad 均有可操作的碎片尺寸。
- 百级碎片量下局内交互保持 60FPS。
- 生成结果通过面积、重叠、自交、碎片数量和可操作性检查。
- 同一种子在同一版本下可重现。

## 12. 最终推荐

如果只能选择三个新方向：

1. **花窗铅线**：强化项目独有的彩色玻璃艺术身份。
2. **雷击裂纹**：提供自然、强烈、易于传播的视觉和拓扑差异。
3. **玩家亲自下刀**：让玩家参与生成内容，打开自定义、分享和好友挑战空间。

如果只能选择一个长期架构方向，应优先完成：

> `几何生成器 + 规则变异器 + 确定性种子 + 边界元数据`

这套基础可以支撑未来的花窗、裂纹、螺旋、盲拼、逐层再切、双人挑战和用户创作，而不需要为每一种玩法继续复制一套独立的拼图生成逻辑。
