## 0. 文档定位

本文档不是新 PRD，而是一张**"地图"**：把已实现的地基、docs 里已沉淀的构想、本轮新联想、以及 AI 联合的远期愿景，放到同一张全景图上，并给出分阶段路线。

- 详细设计以各自文档为准，本文档只负责**索引、映射、排序与判断**。
- 核心命题：**所有未来构想，都站在同一套已验证的几何核心之上**——这是本项目最大的资产，也是路线规划的前提。

## 4. 本轮新联想与映射（2026-09）

| 新联想 | 与既有构想的关系 | 判断 |
| --- | --- | --- |
| 照片效果应用（一键马赛克 / 一键水彩） | ≈ 彩色玻璃概念文档的 **Custom Photo Mosaic**（上传照片 → Sobel 边缘检测 → 采样色彩） | 重叠；用户补上"滤镜产品视角"，可强化为入口隐喻 |
| 教堂彩色玻璃窗（碎片拼成斑斓图案，让人有共鸣） | ≈ `stained-glass-art-platform-concept.md` 完整概念 | 印证；docs 早已想到，且共鸣点正是该概念的定位核心 |
| 立体雕塑 3D（立体碎片拼贴成花瓶） | 现有文档**无覆盖** | ★ 新空白；技术跨度最大，见 §6 P2 与 §7 风险 |

**对 3D 立体拼贴的构想记录**（用户原话精神）：

- 形态 A（2.5D 展开）：花瓶等回转体，把 3D 表面**展开成 2D 拼图**拼好后"包裹"成型——复用几何核心，但需新增"表面参数化"模块。
- 形态 B（真 3D 装配）：多面体碎块在三维空间拼装——几何核心需要从 2D 多边形跃迁到 3D 多面体，是真正的算法级重构，属于 AI 联合的远期课题。

## 5. 共性资产：几何核心复用矩阵

| 构想 | 增量切割 | Voronoi 马赛克 | 难度体系 | Canvas 渲染 | 云端数据 | 确定性 PRNG |
| --- | :-: | :-: | :-: | :-: | :-: | :-: |
| 彩色玻璃花窗 | ○ | ● | ● | ●（需透光渲染） | ●（画廊/挑战种子） | ●（同题种子） |
| 照片→马赛克 | ○ | ● | ● | ● | ●（作品存储） | ○ |
| 每日挑战 | ● | ● | ● | ● | ●（日榜） | ●（必需） |
| 盲拼模式 | ● | ● | ● | ● | ●（评级档案） | ○ |
| 禅意模式 | ● | ○ | ● | ●（主题视觉） | ●（时长统计） | ○ |
| 3D 立体拼贴 | ○ | ○ | ○ | 需 3D 渲染 | ○ | ○ |

● = 直接复用现有能力　○ = 需要新增能力

**结论**：彩色玻璃与照片马赛克的复用率最高（≈ 80% 直接复用）；3D 拼贴复用率最低（需重写几何与渲染两条链路）。

## 6. 分阶段路线（路线图）

### P0 · 近期（复用核心，纯 2D）—— 与 PRD v2.0 R0-R1 对齐

- **PRNG 确定性底座**（R0）：每日同题、公平榜、回放的前提，所有模式的前置依赖。
- **Lobby 模式大厅**（R0）：四模式卡片、最近进度、今日状态。
- **彩色玻璃马赛克模式 MVP**（本路线的首选新增）：复用 Voronoi + 增量切割 + 云端；先做"纯随机花窗"（Pure Mosaic）单模式验证共鸣。
- **照片→马赛克 MVP**：Custom Photo Mosaic 的简化版（上传 → 边缘检测 → 彩色玻璃碎片）。
- 验收：拼接完成率、二次进入率、分享转化。

### P1 · 中期 —— 与 PRD v2.0 R2-R3 对齐

- 每日挑战全量（DNF 状态机、日榜、重拼）。
- 盲拼模式（评级体系、段位档案）。
- 禅意模式（环境音、完成仪式、时长解锁）。
- 拼图师档案 / 个人画廊；时光回放短视频（传播钩子）。

### P2 · AI 联合远期（超出纯几何本地能力，与 AI 大模型联合实现）

- 照片 → 艺术风格化（水彩 / 玻璃质感 / 素描线条），再由生成式几何切割成拼图。
- AI 生成图案线条（花卉、飞鸟、天体等主题轮廓，替代手工矢量）。
- **3D 立体拼贴**（先 2.5D 展开验证，再评估真 3D）。
- "有共鸣、有所得"的主题化拼图（故事、文化、记忆载体）。

### 路线原则

- 单作者产能有限：**一次只推一条主线**；每条主线的玩法文档须先评审定案再进入实现（沿用 PRD v2.0"独立策划文档 → 评审 → MVP"的门槛）。
- P0 推荐主线：**彩色玻璃模式**——复用率最高、共鸣最强、社交传播天然（成品即艺术品）。

## 7. 风险与判断

| 风险 | 等级 | 对策 |
| --- | --- | --- |
| 3D 拼贴的算法跨度（2D→3D） | 高 | 先做 2.5D 展开验证；真 3D 列为 AI 联合远期，不与 2D 主线抢资源 |
| 范围膨胀（v2.0 教训：首发曾过大） | 高 | 严格按"独立文档 → 评审 → MVP 切片"推进，P0 只发布 1-2 个强感知模式 |
| 共鸣型游戏的度量（"欢喜/有共鸣/有所得"如何量化） | 中 | 用健康指标代理：完成率、二次进入率、分享/导出率、停留时长（沿用各模式文档的验证目标） |
| 彩色玻璃的透光渲染性能（50-200 片长局） | 中 | 概念文档已建议 WebGL/Three.js + Web Workers；MVP 可先用 Canvas 2D 验证玩法再升级渲染 |
| 单作者 + 多代 AI 协同的节奏 | 低 | 延续现状：核心算法强验证 + CI 门禁 + 人工实测；每阶段以"可交付、可自测"为界 |
